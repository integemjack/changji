# 改这个仓库之前先看这份

场记 changji：把一堆生成模型串成短剧生产线的编排层，**一个二进制**
（界面 + 接口 + 编排 + 出图 + 出片 + 配音 + 大模型全在进程内）。
这份文件是**索引 + 容易踩错的地方**，长篇说明在 [docs/](docs/)，
产品介绍在 [README.md](README.md)。

## 代码地图

```
cpp/src/
  main.cpp            入口、命令行（--doctor / --say / --port / --worker）
  http/               路由和接口。server.cpp 是总路由表；
                      readonly/projects/episodes/planning/scripting/batch/run
                      /config_api 各管一摊；run_deps.cpp 组装后端（池、farm）
  pipeline/           一集怎么跑：episode.cpp（阶段编排）、jobs.hpp（作业表、
                      进度、取消）、shot_flow.hpp（首帧和出片的排位）
  stages/             每一步的纯逻辑：story_outline / story_analyze /
                      chapter_write / script_story / storyboard / frames /
                      render / audio / bible / assemble
  infer/              派活：worker_pool（池）、worker_farm（本机多卡拉子进程）、
                      worker_server（工作进程那套接口）、node_registry（机器表）
  llm/                大模型客户端。**schema 以文字贴在提示词后面**，见下
  media/              时间轴、切集、ffmpeg 参数
  models/             Shot / Project / AssetLibrary / Story 这些数据结构
  gates/              质量闸门（硬切、时长、响度、参考图）
  config/             配置读写。机器的设置和剧的设置分两处
cpp/prompts.toml      所有提示词。构建时由 tools/gen_prompts.py 生成成头文件
cpp/tests/unit/       doctest。**基线是 4 个红**，见下
webapp/client/        Vue 3。打包后嵌进二进制（tools/gen_webapp.py）
```

## 常用命令

```bash
# 本机（仓库在 changji/，构建目录在它外面一层）
cmake --build ../build -j8                      # 引擎
cmake --build ../build_tests -j8                # 单元测试
../build_tests/changji_tests                    # 跑全部；-tc="用例名" 跑一条
(cd webapp/client && npm run build) && python3 cpp/tools/gen_webapp.py   # 改了前端要这两步
pkill -f 'build/changji [-]-port'
(cd .. && nohup ./build/changji --port 8080 > /tmp/changji8080.log 2>&1 &)
```

- **macOS 没有 `setsid`**，本机起服务用 `(nohup … &)`。
- 改了 `webapp/` 一定要**重新打包再 gen_webapp 再编引擎**，否则跑的是旧界面。
  `npm run build` 会先跑 eslint，**有 error 时 vite 根本不构建**——只看
  "embedded" 没看 lint 的话会把旧包嵌进去。

## 测试基线

**全量 1158 条，应该全绿。** 红了就是真红了，别当背景噪声。

2026-09-17 之前这儿写的是「4 条红」——那是四份当年冻下来的 Python 答案，
用来证明移植没走样。**Python 引擎 2026-09-10 就删了**，那个用途从那天起就
没了；断言还在，实际效果变成「提示词和 schema 永远改不动」。那一天里它挡住
了三处量出来的改进（`camera_move` 的分类式禁令、从没被填过的 `visual_desc`、
schema 的排版），用户拍板退役。

退掉的不是"有守卫"，是"守卫钉的是什么"：

| 原来 | 现在 |
|---|---|
| 整份 schema 逐字节比 | 钉**结构**：字段在不在、必填掉没掉、没人读的栏有没有偷偷回来 |
| 提示词逐字节比 | 剧本那三条还留着（`test_script.cpp`），用途是**快照**：改了连语料一起改，让它在 diff 里看得见 |
| —— | 加了一条**预算线**：分镜 schema 贴过去不许超过 6200 字符 |

判据：**会不会真出事**。字段名错、某一栏掉出 `required`（模型整个略过那一
栏，全程不报错）是真出事；改一句描述不是。

## 最容易踩错的地方

### 一、没有语法层

2026-09-14 起**结构约束整个交给提示词**：本地 GBNF 随本地后端删了，
`response_format` 也不发（各家支持得七零八落）。`llm::schema_as_prompt`
把 schema **当文字贴在提示词后面**。所以：

- `enum` / `required` / `minItems` / `maxItems` 对远端模型**只是建议**，
  `schema_validate.hpp` 里写着「这些模型根本不按 GBNF 生成」；
- 说"这条规则 schema 管着了"时，意思只是"同样的话在 schema 那半截里也有"，
  **不是"它没得选"**；
- schema 是提示词里最大的一块（分镜那份贴过去 5600+ 字符，规则表才 859），
  改它就是改约束本身。

### 二、砍提示词的判据（三条，缺一条就会砍错）

1. **字段描述只管得住那一栏。** 要管所有栏的规则（「哪一栏都不要写长相」）
   留在规则表里——实测长相会写进 `summary`。
2. **搬进 description 之前先看那一栏归谁管**。2026-09-17 之前这儿写的是
   "先看有没有对拍语料钉着"——那几份语料当天退役了（见测试基线）。现在钉
   schema 的是结构守卫：加字段、改描述都不会红，**删字段和动 required 会**。
3. **只有这一次调用自己收得到的东西才算"已经管着了"**。拿另一个阶段的
   schema 当理由是错的——那是另一次调用，根本收不到。

### 三、量比例再动手

说"太臃肿"时先量组成。2026-09-17 的实证：砍规则表一整天省 1294 字，而
schema 那几笔省了四千多，**一个字的约束都没丢**。
**臃肿长在没人看的地方**（`dump()` 出来的 schema、成片目录里的文件）。

分镜那份 schema 真正发给模型的字数，一天之内：

| | 字符 | 动的是什么 |
|---|---|---|
| 缩进 2 | 9300 上下 | —— |
| 缩进 1 | 7438 | 排版；外加摘掉没人 `$ref` 的 `$defs`、beat 提成 `$ref` |
| 缩进 0 + 摘 title | **5573** | 排版；外加 pydantic 自动生成的 `title` |

同一条提示词里那张硬性要求表才 859 字符。**换行要留**（压成一行连括号配对
都要一个一个数），缩进的空格不留。

⚠️ **摘 `title` 要分清一层**：`properties` 底下那一层的键是**字段名**，
剧本那份 schema 里真有一个叫 `title` 的字段（一集的标题）。递归摘会把它整个
删掉，模型于是再也不填标题，而且一声不响。

`test_storyboard.cpp` 里有一条**预算线**用例（不许超过 6200 字），
schema 悄悄涨回去时它先红。

查质量问题同理：从**产出物往回查**（`output/`、`subtitles/` 里的文件名、
时长、数量）比从代码往前读快得多。

### 四、别拿数量当判据

`!shots.empty()` / `shots.size()` 回答不了「这一章有没有分镜」——它只是在
数据干净时碰巧相等。2026-09-17 一天里撞了三处，根子都是这个：

- 批量补分镜判 `!ep.shots.empty()`，于是一章 17 个**空壳**镜头
  （`shot_id` 是空串）被当成"已经有分镜"跳过，一键跑完整部剧也救不回来；
- `/api/project` 每一集报的 `shots` 是数组长度，而它同时是三处的判据
  （顶栏步骤对勾、按钮上的「还差 N 章分镜」、下拉里的「（17 镜）」）；
- 改完上面那个之后，同一份回包里的 `status` 计数表还在数全部——**而界面
  拿这两个数相减**算「还差几镜出片」，一个数全部一个数能用的就会漏算。

两条规矩：
1. 判据写成**正面的条件**（"有没有一镜能用"），不是"数组非空"。
2. 改一个数的口径时，**把用同一批数据的所有出口一起改**——尤其是同一份
   回包里会被相减的那几个。

### 五、禁令要写成一步能答完的

2026-09-17 从模型自己的思考流里读出来的（任务页面那个「思考」第一次派上用
场）：规则写成**"不要属于某一类的东西"**时，模型会对**每一个**候选做一次归
类判断，而那笔开销比规则本身大几个数量级。

  · `camera_move`：「只有定格的物件特写、静止的空镜才填 static」——它对每一
    镜重新论证一遍，原话「a hand pressing a button is an object close-up
    with motion… Strict compliance → no static. Use push_in. Eh — that's a
    lot of push_ins」，一场戏想了十五万字、十三分钟。
  · 「不要描述服装」——它卡在「帆布手套算不算服装」上，而那是剧本里写着、
    动作要抓着的东西。

改法不是砍掉禁令，是**把判据换成一步能答完的**，并且**说出什么是允许的**：

| 原来 | 改成 |
|---|---|
| 只有定格的物件特写才填 static | 画面里没有任何东西在动时才填 static |
| 不要描述长相、发型、服装 | ……的款式和颜色；但身体要在场：手在干什么、衣服湿没湿 |

另一条同源的实证（2026-09-17，两个项目两个模型）：**说清分布管用，说"不要
某一类"不管用**。景别那条写了明确分布（「主力是 MS / MCU，占一半左右」），
两个模型出来几乎一样（MCU 38% / 40%）；运镜那条只写「不要整场都用同一个」，
两个模型各自抱死一个不同的值（static 56% / push_in 58%）。

**扫过一遍，别再重复砍**：规则表里 64 条禁令形状的句子，绝大多数是**具体**
禁令（「不写开门开窗」「不要带引号」「不要副标题」），评估成本很低，不用动。
要做归类判断的只有"长相/服装"和 static 那两族，而"长相"那族在最热的两处
（`chapter_write`、`script_story`）本来就带着正面判据。

### 六、引用规矩引原话，别引条号

提示词那几张表一砍就重编号，注释里写「第 14 条」当场指歪。原话能 grep，
条号不能。（`storyboard.cpp` 上就写着这条，2026-09-17 又犯了一次。）

### 七、并行那一段一个字节都不往 Shot 里写

`frames` / `render` / `audio` 三层都是"各路跑副本 → 收完在调用线程上按原
顺序写回"。写回的凭据是 **`Done::ran`（正面判据）**，不是"没被标成跳过"
——2026-09-17 就是靠后者丢了一整集：某条路径提前 return，一格都没标跳过，
收尾时把 17 镜全写成了默认构造的空壳（`shot_id` 变空串）。

### 八、同一件事别在两处各写一遍

2026-09-17 一天撞了四次，每次都是"改了一处，另一处静悄悄不跟"：

| 撞到的 | 后果 |
|---|---|
| 成片文件名归属（清理一处、计数一处各判一遍） | 清理认两种命名、计数只认一种，切过的章全漏 |
| 提示词规则的**条号**（注释里写「第 14 条」） | 表一砍就重编号，指歪 |
| 阶段文案（引擎 `kLabels` / 前端 `STAGE_LABELS`） | 改了前端，预估行还是旧词 |
| 「人按的停」那两句话（散在六个字面量里） | 界面靠正则认它，改字就把取消显示成红报错 |

处理办法按顺序挑：**收成一处**（`media::episode_of_output`、
`util/cancel_words.hpp`）；收不动就**让它会响**（跨语言那条用例直接读 C++
源码）；**引原话不引条号**。

### 九、排队这件事归引擎记，不归页面

2026-09-17 一天里这一处改了四版，用户说了三次才对。原来「一键出图」是**页
面**问一遍池里有几个位置、照着开几条道、每条道自己往下取下一张。三处不对：

| 撞到的 | 用户原话 |
|---|---|
| 页面手里只有"正在画的那几张"，说不出还排着几张 | 「排队被你吃了？」 |
| 队列活在标签页的闭包里，关掉就散 | —— |
| 位置数是按下去那一刻的快照，中途加机器不跟 | —— |

收到引擎之后（`http/ref_gen.cpp` 的 `RefQueue`），还要分清两件事：

1. **「派出去了」不等于「正在画」。** 池开的路数比位置数多
   （`infer::pool_lanes`：跨机的每台再加一路，为的是拉产物那几十秒里
   把下一件先派出去）。双卡机四路两卡，照实报四张"在画"又会读成四张在动。
   **真在画的自己会报进度**（`ref_progress`），拿它分。
2. **还没派出去的那几格要写「等待中」。** 不写的话它和"根本没排上"长得
   一模一样（用户：「明明没有开始的，不是应该显示等待中吗」）。

还有一条**名字**：那一行报的是「董平 正面」不是「董平」——同一个人的三张
挤在一行里，只报名字就是三个一样的词（用户：「后面名字都一样，谁知道你在
出哪个」）。

### 十、一件活登记在哪儿：任务账本

2026-09-17 起**只有一本账**：`pipeline/task_board.hpp`。三个状态（排队中 →
正在做 → 做完的），一件活一个 `Task`，构造即排队、`begin()` 即开工、
**析构即结账**。`Activity` 是它的壳（构造即 begin），`JobTable::start` 起的
长跑任务在自己那条线程上也开一个。

要加一族新活的话，三条：

1. **开工之前就把整批登上去**，不是领到活才登记——不然"排队中"那一栏永远
   是空的。登记点看 `ref_gen.cpp` 的 `enroll`、`frames/render/audio.cpp` 里
   那几段 `tasks.reserve(total)`。
2. **结账是"这一件干完那一下"**，不是整批收尾。留到收尾一起放手的话，每一
   件的耗时都变成"从自己开工到整批结束"——实测六张参考图全报 96.9 秒，
   而真实是 36 到 73 秒不等。
3. **名字要说清干什么**：「配音 · sh004「快走，从后门。」」，不是「配音」。
   一集二十行长得一样的话，那一栏等于没有。

每一件自己的令牌用 `CancelToken::link` 挂在整批那个令牌上。没有这条的话
「停一件」和「停一整批」只能选一个。

思考走 `thinking_sink`（没有 stream 也回一个函数，往当前线程那件活上接）。
**账里只报有没有、多少字**，正文另走 `/api/task/thinking`——一次写作的思考
几千字，而这份账两秒推一次。

### 十一、比项目路径要规范化再比

队列里存的是 `ProjectStore::root()`（规范化过的），问的那头给的是界面手里
那串。macOS 上 `/var/folders/…` 是 `/private/var/folders/…` 的软链，**两串
字不一样而指的是同一个地方**。直接比字符串的后果是"问了等于没问"：这一批
明明在跑，快照回「没在跑」。`ref_gen.cpp` 的 `same_project` 走
`fs::weakly_canonical`。

### 十二、多机互联

**一台机器 = 一个 `changji` 进程 = 机器表里一条 `[[peer.nodes]]`**，指主
服务端口。那个进程自己按显卡数拉起 `--worker --gpu N` 子进程（`worker_farm`），
外面只连主端口。别手工起 worker、别一台机器连两次。

`/status` 里报 `slots`（= 活着的子进程数），派活那头按它开槽
（`infer::remote_slots_for`）——不报的话一台双卡机只会被当成一个槽。

## 远端那台（有显卡的）

```
root@43.110.148.239   两张 NVIDIA L20（46 GB）· 32 核
仓库 /root/changji-src/changji/      构建 /root/changji-src/build
```

```bash
rsync -rlz cpp/src/  root@…:/root/changji-src/changji/cpp/src/     # 不要用 -a
ssh root@… 'export PATH=/usr/local/cuda/bin:$PATH; cd /root/changji-src && cmake --build build -j32'
ssh root@… "strings build/changji | grep -c cublas"                # 必须 > 0
ssh root@… "pkill -9 -f 'changji [-]-host'"                        # 和启动分两次 ssh
ssh root@… "cd /root/changji-src && (setsid nohup ./build/changji --host 0.0.0.0 --port 8080 > /root/changji.log 2>&1 &)"
```

- **`pkill` 和启动必须分两条 ssh 命令**，写在一起会把自己那个 shell 也匹配掉（退出码 255）。
- GPU 构建要 `CHANGJI_SD_CUDA=ON` / `CHANGJI_CUDA_ARCH=89`。
- 远端 `/status` 有口令门，直接 curl 是 401；看本机 `/api/nodes` 里那一行更省事。

## 工作习惯

- **验证顺序：页面 → 本机后台 → 远程。** 只看接口会漏掉崩溃和 GPU 空转；
  编译重启完把 http://127.0.0.1:8080 打开，导到这次改动看得见的那一页。
- **能自动解决的就别报错。**
- **只 commit，不 push。** push 只在当次明确要求时做。
