# 模型选型结论

调研时间 2026-09-06。硬件约束：RTX 5080 16GB 显存，31GB 内存。

## 已实测的产能数据

同一条 Wan 2.2 TI2V 5B 链路，本机实测：

| 档位 | 分辨率 | 帧数 | 步数 | 生成耗时 | 片长 | 实时比 |
|---|---|---|---|---|---|---|
| 草稿 | 640x352 | 121 | 10 | 27 秒 | 5 秒 | 5.4 倍 |
| 预览 | 960x544 | 121 | 20 | 120 秒 | 5 秒 | 23.9 倍 |
| 成片 | 1280x704 | 121 | 30 | 392 秒 | 5 秒 | 77.7 倍 |

成片档单机 24 小时理论上限约 18 分钟成片。草稿档比成片档快 14.4 倍，
这个差价是分级生成策略可行性的来源。

## 推翻的早期建议

这三条是本次调研推翻的，早先给出过但不适用：

| 早先说法 | 实际情况 |
|---|---|
| IPAdapter 锁脸 + ControlNet 锁姿势 + StoryDiffusion | StoryDiffusion 是 SD1.5/SDXL 时代产物，DiT 架构无对应实现。IPAdapter 系只锁脸不锁发型服装，而短剧最易崩的正是后两者。已退居二线 |
| LatentSync 1.6 本地首选 | 官方推理需 18GB，ComfyUI 封装节点标 20GB，16GB 跑不了。只能退回 1.5 版，但 1.5 牙齿嘴唇有模糊 |
| Fish Speech 作为 TTS 备选 | 代码 Apache 2.0 但权重是 CC-BY-NC-SA-4.0，不可商用 |

## 图像端（角色与场景一致性）

核心思路：一致性靠图像端锁死，视频模型只负责 3 到 5 秒的运动，不负责跨镜头记忆。

| 用途 | 选型 | 许可证 | 显存 |
|---|---|---|---|
| 逐镜首帧 | Qwen-Image-Edit-2511 | Apache 2.0 | GGUF Q4_K_M 约 13.2GB |
| 换机位 | Multiple-Angles LoRA | 随基座 | 叠加 |
| 角色 LoRA 训练 | musubi-tuner | Apache 2.0 | 图像端 12GB+ 够用 |
| 快速草稿 | Z-Image Turbo | Apache 2.0 | 6B，很省 |

Qwen-Image-Edit-2511 的模型卡明确写了修复角色漂移，支持 1 到 3 张参考图，
可同时喂角色定妆图和场景空景图。这是双风格都能共用的一环。

角色 LoRA 训练用 musubi-tuner，不要用 ai-toolkit（后者训 Qwen-Image 需 32GB）。
素材 20 到 40 张，rank 32 alpha 16，lr 2e-4。5080 上估计 3 到 5 小时一个角色。
只训图像端，视频端 LoRA 在 16GB 上极其痛苦且 Wan 2.2 是 MoE 双专家要训两份。

## 视频端

| 用途 | 选型 | 说明 |
|---|---|---|
| 图生视频主力 | Wan 2.2 TI2V 5B | 已装。只吃首帧，做不了首尾帧 |
| 首尾帧衔接 | Wan2.2-I2V-A14B GGUF | 需补装。用 WanFirstLastFrameToVideo 节点 |

已确认的坑：单段超过 120 帧会在约 100 帧处到达末帧后往回跑，出现乒乓现象。
首尾帧接龙每次 VAE 重编码，接 3 到 4 段后画质明显下降并累积色偏。

结论：短剧不追求一镜到底。3 到 5 秒一切靠剪辑，比接龙划算得多。
接龙只用在同一镜头需要 8 到 10 秒的少数场合。

## 配音

只列可商用的。权重和代码许可证一致才算干净。

| 选型 | 许可证 | 定位 |
|---|---|---|
| Qwen3-TTS 1.7B | Apache 2.0 | 中文综合最强，主力 |
| Fun-CosyVoice3-0.5B | Apache 2.0 | 方言 + instruct 情感，RTF 0.05 极快 |
| GPT-SoVITS v2Pro | MIT | 按角色微调做固定主演音色，走 api_v2.py |
| MOSS-TTSD v1.0 | Apache 2.0 | 需要整段多人对话韵律时用 |
| Step-Audio-EditX | Apache 2.0 | 情感润色 pass |

不可商用：IndexTTS-2.5（bilibili 许可，商用需书面授权，官方未澄清）、
Fish Speech（权重 NC）、F5-TTS（权重 CC-BY-NC）、MegaTTS3（编码器权重未放）。

ComfyUI 侧生态已收敛到 diodiogod/TTS-Audio-Suite 一个节点包，
覆盖 19 个引擎，支持 SRT 时间轴对齐和方括号切角色，对多角色批量配音很契合。
GPT-SoVITS 不在其中，需单独走 API。

## 口型

| 选型 | 许可证 | 显存 | 定位 |
|---|---|---|---|
| LongCat-Video-Avatar 1.5 | MIT | GGUF Q4_K_S 11.7GB | 首选。Whisper-large-v3 编码器，中文最强 |
| InfiniteTalk | Apache 2.0 | GGUF + block-swap | 主力备选。中文 wav2vec2，支持视频重配音 |
| EchoMimicV3-Flash | Apache 2.0 | 12GB @768x768 | 1.3B，出草稿最快 |
| Wan2.2-S2V-14B | Apache 2.0 | GGUF Q4_K_S 13.0GB | ComfyUI 原生节点，文档最全 |

Wan2.2-S2V 的音频编码器是英文 wav2vec2，中文同步明显偏软。
社区标准修法是换成 TencentGameMate/chinese-wav2vec2-base。

LatentSync 定位不同，它是给已有视频换口型，不生成身体和头部动作，可与上面并存。
但 1.6 版超显存，只能用 1.5。

## 明确不可行

在 16GB 上跑不动或已淘汰的：

- HoloCine 14B：最对口的多镜头方案，但承诺的 5B 版未发布，项目已停更，无 GGUF
- FLUX.2 dev 32B：能跑但速度不可接受
- LTX-2.3 / LTX-2.5：需 24GB 以上
- HunyuanVideo-Avatar：最低 24GB，仅支持 Linux
- Hallo3：训练集只有英文，中文直接出局
- StoryDiffusion：技术代差

## 待验证

- MultiShotMaster 1.3B：16GB 最可行的原生多镜头方案，但需独立 conda 环境且无 ComfyUI 节点
- Wan-Animate-2：2026-08 刚发，Comfy-Org 已有 int8 权重，社区实测极少
- Krea 2：许可证是 Community License，年营收低于 100 万美元才免费商用，变现前要读条款

## 不实信息提醒

不存在 Wan 2.5 / 2.6 / 2.7 / 3.0 的开源权重。2.5 及以后是 API 商用版。
若干站点声称的开源发布，背后没有仓库没有模型卡，判定为 SEO 内容农场。

# 动漫线选型

## 关键结论：视频环节几乎零重构

Index-AniSora V3.2（B站）就是基于 Wan 2.2 做的动漫专用分支，权重 Apache 2.0。
QuantStack 已有 GGUF 量化版，可直接用 Unet Loader (GGUF) 替换现有工作流里的 UNet。
训练数据一千万条动漫数据，用了 RLHF。能力覆盖图生视频、关键帧补间、
局部区域引导动画、姿态深度线稿多模态引导、超分到 720p/1080p。

这是动漫线成本最低的接入点。

## 出图基座

| 选型 | 许可证 | 显存 | 判断 |
|---|---|---|---|
| Neta Lumina | Apache 2.0 | 8GB+ | 商用最干净。Gemma-2B 编码器原生支持中英日，中文提示词直出 |
| Illustrious / NoobAI / WAI | FAIPL-1.0-SD | 6-10GB | 生态最厚但许可证有陷阱，见下 |
| Anima 2B | 非商用 | 6-8GB | 画质新，输出图可商用但模型本身不可商用 |
| Z-Image-Turbo + 动漫 LoRA | Apache 2.0 | 6B 很省 | 与写实线共基座 |
| FLUX.2 klein 4B | Apache 2.0 | 约 13GB | 4B 同时做生成、编辑、多参考 |
| ERNIE-Image 8B | Apache 2.0 | 有 GGUF | 擅长海报、漫画分镜、多格排版、中文字渲染 |

## 许可证陷阱

FAIPL-1.0-SD 要求衍生模型、融合模型、LoRA 必须以同协议开源。
用 Illustrious 或 NoobAI 训的角色 LoRA 不能当私有资产闭源商业化。
生成的图片输出一般可商用，但模型资产本身受限。

想要商用无争议，动漫基座选 Neta Lumina（Apache 2.0）。

Anima 的非商用限制只针对模型本身，不针对输出，生成的图片可以商用。

## 动漫角色一致性比真人便宜一个数量级

原因是动漫角色一致性靠可枚举的符号集：发色、瞳色、发型、饰品、服装。
Danbooru 标签体系已把这套符号 token 化，光靠固定 tag 串就能拿到
70 到 85 的跨镜一致性，零成本。真人线拿不到这个红利。

分层策略：
- 主角 2 到 3 个训 LoRA。三视图到自蒸馏到 30 张素材，16GB 上 20 到 60 分钟
- 配角群演用 tag 串加 Qwen-Image-Edit-2511 参考图，不训

三视图和设定集在 2026 仍是主流，而且被强化了，因为商业平台都是资产库模式。

一个实测发现：从 Danbooru 爬的图风格杂、服装细节不稳。
改用一致性生图模型先造一批高一致性训练图，效果反而更好。
可以用 Qwen-Image-Edit-2511 造训练集。

## 动漫口型必须避开的坑

基于人脸检测加嘴部区域重绘的方案在二次元上会失败。
Wav2Lip、MuseTalk、LatentSync、SadTalker 都是在真人脸上训练的，
动漫脸经常检测不到，即使检测到，嘴部重绘会产生真人皮肤纹理伪影，
动作也僵硬，因为真人语音的运动先验迁不到风格化角色。

动漫线必须用视频扩散式、不依赖人脸裁剪的方案：
- InfiniteTalk v1.5：明确写了泛化到动漫域，Apache 2.0
- MultiTalk：明确支持卡通角色，最长 15 秒
- AniSora 自带的 lipsync 模块，动漫原生训练

漫剧的实用降级：很多商业漫剧不做精确口型，嘴部只做张半张闭两三帧循环，
或者干脆静止，靠字幕加配音加表情切换承载。这能省掉整个口型环节的算力。

## Wan 2.2 的写实偏置

社区共识是 Wan 2.2 有强烈写实偏置，动漫输入会被往写实拽。
对策是负面词加 ((realistic))，动漫风 LoRA 强度提到 1.0 到 1.2。
或者直接换 AniSora，从根上解决。

AnimationBench 显示 Wan2.2 是开源里最强的，但 AniMatrix 这个动漫专项基准显示
它在动漫的提示理解和结构稳定性两项上得分最低。AniMatrix 本身效果好但权重未发布。

## 漫剧形态的六个流程简化

漫剧介于传统动画和真人短剧之间，静态漫画画面为基底，图生视频让画面动起来。
单集 3 到 5 分钟，竖屏 9:16。相比全动态视频短剧：

1. 镜头只需 2 到 4 秒轻微动效，头部微转、发丝随风、镜头缓慢推进。
   运动幅度必须调低否则人物崩坏。视频生成的时长分辨率步数压力全面降低
2. 相当比例的镜头根本不用视频模型。静帧加 Ken Burns 运镜加图层视差加转场，
   FFmpeg 就能做。行业叫静态关键帧加动态过渡
3. 一张图等于一个镜头，不需要跨镜动作连贯性。分镜稿本身就是成片素材
4. 角色一致性降级为同一张立绘反复复用，换背景换表情换景别
5. 口型可省或极简
6. 改一处全剧同步，可资产化

## 两条线的共用与分叉

完全共用：剧本和结构化分镜、编排层、角色资产方法论、
ControlNet 预处理器、视频骨架（都是 Wan 2.2 家族）、
TTS、口型（InfiniteTalk v1.5 两条线都能用）、字幕对齐、FFmpeg 后期、插帧。

必须分叉：

| 环节 | 写实线 | 动漫线 |
|---|---|---|
| 出图基座 | Qwen-Image-Edit-2511 | Neta Lumina 或 Illustrious 系 |
| 提示词范式 | 自然语言长句 | Danbooru tag 串。两套模板库两套负面词 |
| 采样参数 | 各基座习惯不同 | 同左 |
| 一致性手段 | 多参考图不训练 | tag 锁定加角色 LoRA |
| 视频风格约束 | Wan2.2 原生 | 换 AniSora 或加 anime LoRA |
| 超分 | RealESRGAN / SUPIR | 必须 anime 专用。通用超分会把平涂搞出假纹理 |
| 口型策略 | 必须精确 | 可退化甚至不做 |
| 画面节奏 | 需要真实运动 | 静帧加运镜可占相当比例 |

## 分镜表字段（两条线共用）

行业标准表的字段：镜号、景别、运镜、画面详细描述、角色台词、情绪、单镜头时长。
这套 schema 两条线直接共用。
