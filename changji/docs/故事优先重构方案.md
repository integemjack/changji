# 故事优先重构方案

2026-09-11 定，当天做完。分两块：**故事层**（引擎，第一到三节）和
**页面重排**（界面，第四节）。

第四节写的是**最终落地的样子**，不是最初的设想——最初想的是「八页收成
两页」，做下来是四格加一条项目栏，差在哪、为什么改，那一节里说了。

## 一、为什么改

原来写整季是这样的（`http/batch.cpp` 的 `post_script_series`）：

```
for i in 1..N:
    prompt = 一句梗概 + 最近三集剧本原文 + 已有角色名
    draft  = LLM(prompt)
    新建一集，存进去
```

`previous_context()` 只取最近三集，还按 4000 字符截断；集数 `episodes`
是个 1..20 的入参；角色库由 `post_bible` 从**第一集有内容的剧本**提。

四个后果，每条都直接来自上面三行：

| 现象 | 原因 |
|---|---|
| 没人规定第 N 集该发生什么 | 循环里除了梗概没有全局结构 |
| 写到第五集开始失忆，伏笔接不上 | 只带前三集、4000 字符 |
| 故事没有终点，写满 N 集就停 | 集数是人拍脑袋填的 |
| 角色和场景是增量拼的 | bible 从单集剧本提 |

最后一条最要紧：README 里「角色一致性做成结构约束」这条设计，**在集内成立，
跨集是漏的**——那个「全剧共用的资产库」其实是从第一集推出来的。

改成：**先有完整故事，从故事提人物关系和场景，再按每集时长把故事切成集。**

## 二、故事分三层，不是一次生成

一个二十集的故事十几万字，大模型一次吐不出来，也塞不回上下文。所以：

```
梗概（一两句）
  ↓
故事大纲（分章，每章三五句 + 人物关系 + 场景表）   ← 短，一次生成得完
  ↓
章节正文（逐章展开，每次带「全局大纲 + 人物表 + 上一章结尾」）
```

**中间那层是压缩的全局记忆。** 今天的失忆不是因为「逐集写」，是因为没有一份
压缩的全局状态可以每次都带上——只能带前三集原文，带不下就截断。有了大纲，
写第二十章时第二章埋的伏笔照样在上下文里。

### 用户给什么

**故事体量 + 每集时长**，不给集数。集数是算出来的。

什么约束都不给，模型写出来的故事长度是随机的：同一句梗概可能给一个三章就完的
段子，也可能铺开二十章。所以体量这个决定躲不掉，只是不该用「我要写 N 集」
来表达。

### 故事从哪来

三个入口，产物都是同一个 `Story`：

- **AI 写**：梗概 → 大纲 → 正文
- **粘贴**：已有的小说/剧本文本，切成章节
- **关键词**：给方向，走 AI 那条

联网搜热点**不做**：这是本地单二进制、进程内跑的程序，没有检索的路子，加进来
是新增依赖加合规问题。粘贴入口已经覆盖「我自己找到的素材」这个需求。粘别人的
作品是用户自己的事，界面上提一句版权自负，不内置抓取。

## 三、分集怎么算

见 `stages/story_plan.hpp`。要点：

1. **每集容量**按原文字数估：`prose_budget_chars(时长)`。
2. **切点只能落在钩子上**。短剧每集结尾必须是悬念、反转或情绪落点，这是完播率
   的要求，不能按字数硬切。章节里的候选钩子由大纲阶段标出来（`Chapter.hooks`），
   **章界永远是一个候选**。
3. 贪心：从当前位置往前一个容量，取离理想位置最近的那个候选。
4. **尾巴不单切**：剩下的不到 1.3 个容量就并成一集，宁可一集长些，也不留一个
   十几秒的尾巴。
5. **没有正文的章节按「一章一集」**。大纲阶段章节本来就是按情节单元分的，
   一章一集是合理的初始猜测；正文展开之后重算会更准。

字数换算那个系数（`kProseCharsPerSecond`）是**估的**。真实时长以配音为准——
这是 README 里「配音先行」那条规矩，分集表只是建议，人可以调，成片之后某集
明显超或欠，界面上提示重算。

## 四、页面：落地成四格 + 一条项目栏

原来的方案写的是「八页收成两页」。**实际落地是四格**，记在这里免得照着
上一版去找不存在的页：

```
顶栏：  场 │ 📁项目名 │  项目  故事  设定  这一集 ▾ │  ●引擎  ☾  ⚙
侧栏：  项目库（可拖到左边或右边，记住）
```

| 格 | 干什么 |
|---|---|
| 项目 | **这一部剧**：剧名、logline、到哪一步了、这一部自己的设置（画面、全剧风格）、删除 |
| 故事 | 全貌：梗概、体量、章节、**分集切线**、右栏人物地点索引 |
| 设定 | 给故事里的人和地方定妆。关系摆在最上面 |
| 这一集 | `剧本 │ 镜头 │ 成片 │ 发布` 四个视图对着同一集 |

和最初那版的差别，以及为什么：

- **项目库从页面变成常驻侧栏。** 换项目原来要走到第一步那一页、挑完再走
  回来，而当前那一页的状态就丢了。常驻之后点一下就换，人还停在原来那页。
  能拖到左边或右边，记在 localStorage——左右手习惯和外接屏的摆法每个人
  不一样，而这是个选定就不再动的偏好。
- **「项目」还是一格，但它是「这一部剧」不是「挑一部剧」。** 挑那件事归
  侧栏了。
- **画面和全剧风格最终落在项目页**，不在全局设置。一台机器上可以同时有
  竖屏短剧和横屏片子，所以它们是项目级的；而项目页就是这一部剧的地方。
  （中间搬去过设置页的「这个项目」一节，那是还没有项目详情页时的权宜。）
- **「设定」没有并进故事页的抽屉。** 最初想的是右栏索引点开就地定妆、
  连这一格都不要。做到这儿觉得不该：定妆是一摊需要专心的活（传三视图、
  试音色、抠外观词），而且需要一个「谁还缺参考图」的全览——抽屉给不了
  那个。索引点过去仍然是跳到这一格。

### 外壳：六层压成一条

原来顶栏、左侧 StepRail、ContextBar、每页的 StepHeader、内容、底部
stepbar 六层叠着，其中**三层在说同一件事**（rail 的对勾、StepHeader 的
编号徽标、stepbar 的「第 3 / 8 步」），加起来约 190px，而内容区反而最小。

现在一条顶栏装下全部，导航只画一遍。「下一步去哪」原来占一整条 44px，
现在是导航上第一个没做完那一步后面的一个小圆点。

### 继承关系

**主干只能有一个**，选「最难重写的那个」；其余都是搬过去的器官。

| 新页 | 主干 | 搬进来的 |
|---|---|---|
| 项目 | ProjectView | 画面卡、画风卡 |
| 故事 | ScriptView | 预告片、手动加一集（折叠区） |
| 设定 | CharactersView + ScenesView | 关系（新写） |
| 这一集 | ShotsView | ScriptView 的单集编辑器、FilmView、PublishView |
| 外壳 | App.vue | ContextBar 的项目名和集号 |

**别让一个新页有两个主干。** 「这一集」若既继承 ShotsView 的骨架又继承
ScriptView 的页面骨架，结果是两套状态机并存——那正是 ScriptView 自己的病：
它同时是全剧编辑器和单集编辑器，所以谁也做不好。搬进去的是**编辑器**，
不是那一页。

**页面数是给用户的，文件数是给代码的，不用对齐**：

```
ProjectView.vue     这一部剧
StoryView.vue       故事
AssetsView.vue      设定（壳 + 关系）
  assets/AssetCharacters.vue
  assets/AssetLocations.vue
EpisodeView.vue     这一集（壳 + 四视图切换）
  episode/EpScript.vue
  episode/EpShots.vue     ← ShotsView 主体原样搬进来，内部一行没动
  episode/EpFilm.vue
  episode/EpPublish.vue
components/ProjectRail.vue      项目库侧栏
components/AddProjectDialog.vue 加项目弹窗
```

消失的文件：ScriptView、CharactersView、ScenesView、FilmView、PublishView、
StepRail、ContextBar。内容都有去处，不是删功能。

### 这一路踩过的三个「编译过、测试全绿、就是看不见」

界面改动上单测和编译器都拦不住的一类错，都靠实际打开页面才发现：

1. **`.modal` 在三个组件里各写了一份 scoped 样式**，新写的弹窗忘了抄。
   那个类于是没有任何规则——`position: static`，整块落到文档最底下。
   修法不是补第四份，是提到 `styles/base.css`。
2. **光秃秃的 `<template>` 不是 Vue 片段。** 只有带 v-if/v-for/v-slot 的
   才是；没有指令的会当成真的 HTML template 元素渲染，浏览器默认
   `display:none`，内容全在 DOM 里但看不见。
3. **「出片 0%」读起来像在进行中**，而实际是分镜出好了一镜没跑。
   这两种状态下用户要做的事不一样。

第三类尤其说明问题：它不是 bug，是一句写错的话，而写错的话没有任何工具
抓得住。

端到端实跑过一次（故事 → 大纲 → 逐章正文 → 分集 → 落成剧集 → 剧本 →
人物场景 → 分镜 → 配音），跑出来两个真问题，都已修：

- **一章正好写成一集的量**，分集算法等于没干活。根子是「一章该写多长」
  按它要撑起几集算，而大纲阶段一章一集。改成章的篇幅由故事本身定。
- **一集只有一句台词**。剧本提示词把对白字数预算说成了上限，模型就往少里
  写；而更早一版连一句都没有，是提示词没说「必须有台词」。

### 第 7 期：设定那一页到底能干什么

用户定的界限是一句话：**设定里用 AI 的地方只有生成角色图片和场景图片，
内容都在故事里创作完**。照着这句把这一页收了边：

| | 干什么 | 用不用 AI |
|---|---|---|
| 故事 | 唯一的创作源：人是谁、要什么、什么关系、在哪儿、发生什么 | 用 |
| 设定 | ①把故事里的人和地方翻成「可画的描述」 ②照着那份描述生成参考图 | 用 |
| 设定 | **不创作新的人和地方** | — |

落到界面上是三件事：

- 「AI 补新角色」「AI 出这一集的场景」改叫**「照故事定妆」**。旧名字听着
  像这一页会凭空冒出新的人和地方。
- 参考图多了一条来路：**照着那段拼出来的提示词现画**。角色三个朝向，
  场景一张空景。在这之前只能自己上网找图传上来，而这台机器上出图能力
  一直是现成的。
- 外观文字**仍然只存在资产库**，不进故事。存两处必然分叉，而每一镜的
  提示词是从资产库拼的——故事里那份会变成一份没人读、却看着像真的描述。

两条提示词上的规矩用例钉住了，都是「错了不报错」那一类：

- **角色参考图的外观块逐字用 `Character::render_prompt` 那一份**。参考图和
  后面每一镜必须是同一个人，而「同一个人」靠的就是那段字逐字节相同。
- **空景图里不许有人**。空景图是场景一致性的锚点，后面每一镜拿它当底子；
  里面站个人的话，那个人会被当成这个地方的一部分一路复制下去——而那是个
  不属于任何角色、也没法改的人。

画幅这一处栽过一次，值得记：第一版拿的是**档位表**那一档，于是在 5090 上
出了一张 1088×1920、跑了 119 秒，而这部剧每一镜是 544×928。不报任何错，
只是慢一倍、而且参考图和成片对不上。画幅是**这部剧**的属性（项目目录的
`[video]`），不是这台机器的。那段「把项目配置盖进档位表」原来只长在
`run.cpp` 的任务体里，现在抽成 `pipeline::apply_project_spec` 两条路共用。

**还差一步才真闭环**：参考图会原样交给出图模型，但只有图像编辑类模型
（Qwen-Image-Edit、Flux Kontext 这类）真照着画；纯文生图的收下就忽略。
这台机器上配的是 `qwen-image`，所以现在画出来的参考图是「定妆确认」，
还不是一致性锚点。设定页上现在会照实说这句。

### 第 8 期：故事页是个编辑器

用户三句话定的形状：

> 故事这个页面重点在创作，人可以选中某一段让 AI 继续修改优化，
> 也可以通过对话形式修改原稿
>
> 故事页面现在的内容应该都在设定里，分三个 tab，角色，场景，和……
>
> 故事页面应该像程序编辑一样，主要突出写作的过程，
> **ai 生成也应该在编辑器里面流式插入**

落成：

```
故事    原稿。一个编辑器，选中一段就能让 AI 改它
设定    角色 │ 场景 │ 分集      ← 谁、哪儿、怎么切
这一集  剧本 │ 镜头 │ 成片 │ 发布
```

第三格叫**分集**：三个都是名词，都是开拍前要定死的一件事。想过「结构」
（准，但说不出在那儿干什么）和「大纲」（听着像还要再写一遍）。

**一条贯穿的规矩：AI 改出来的东西落在它该在的位置上，不摆在旁边等你抄。**
右边那条栏只剩三样——选中那段的引用、聊过的来回、和一个后悔的口子。

几处踩过或者绕过的坑：

- **编辑器用 textarea，不是 contenteditable。** selectionStart/End 直接就是
  偏移；contenteditable 每次输入都可能重排节点，偏移随时失效——那正是
  「改到一半突然替换错地方」的来源。
- **偏移换算成码点再送给引擎。** 浏览器给的是 UTF-16 单元，碰上代理对
  差一个，而差一个就切在半个字上。
- **服务端回来的故事只刷新没改过的那几章。** 引擎重算分集表也会回一份完整
  故事，照单全收的话正在打字的那一章会被盖掉。
- **有说法的钩子在改稿时要跟着挪、不能被无名的顶掉。** 规则是改动之前的
  照留、之后的整体挪、落在 (a, b] 里的丢掉——右端闭是因为正好落在 b 上那
  个说的是「刚被换掉的那段字悬着什么」。

### 流式：两条路，两种做法

| | 怎么让模型说话 | 为什么 |
|---|---|---|
| 改一小段 | 大白话，不要 JSON | 逐字插的话用户先看到的是 `{"text":"` |
| 写一整章 | 照旧 JSON，在 token 流上抠 text | 那一步还要它标钩子 |

第二条是**不能妥协的**：钩子是一集停在真悬念上的全部依据（实跑把比例从
25% 抬到 70%），为了能流式砍掉它等于拿分集质量换一个动画。所以有了
`stages/json_stream`——一个状态机，边生边把 JSON 里某个字段的字符串值解
出来。它要处理的三种切法都是流式独有的，攒齐了再解析的代码永远碰不到：
转义序列被切在两个 token 中间、`\uXXXX` 被切成四段、代理对高低位分两次到。

链路：llama.cpp 的采样循环 → `llm::Client::complete(req, tok, on_token)`
→ WebSocket（出图的实时预览一直走这条）→ 编辑器。远端那条客户端没实现
逐 token，走的是默认实现（同步跑完整段回调一次）——约定只是「能拿到就早点
给」，拿不到的后端照样能用。

**请求的返回才是权威的那一份**：它解析过、过了守卫、算过钩子，而流出来的
是原始 token。收尾时拿它覆盖一次。

### 编辑器第一次定形（已被下一节替代）

> 留着是为了记住它为什么不行，见下一节开头。

用户 2026-09-11 又定细了一层：**章节用下拉框选，编辑器占满，右下角一排
按钮（自动生成、对话修改、朗读）。**

```
┌────────────────────────────────────────────────────┐
│ [第 3 章 · 雨中告别（1431 字）▾]   全书 4 章·4269 字  [存] │
│                                                    │
│        正文。一次一章，行宽卡在 38 个中文字          │
│                                                    │
│                    [✨重写整章] [对话修改] [朗读]     │
└────────────────────────────────────────────────────┘
```

**一次一章**才谈得上"占满"——十六章连着的话滚动条本身就是干扰。代价是看
不到第三章接第四章那一下顺不顺；换来的是写这一章时眼前没有别的东西。

右下角那排**浮在正文上**，空白处 `pointer-events: none` 不挡选中。三个按钮
**常驻，不看这一章写没写**：写过的点「自动生成」就是重写（先问一句）——
找按钮不用先想"现在是哪种状态"。

批量展开正文时编辑器**跟着翻**到正在写的那一章，除非手上有没存的改动。
那个判据不能用"buf 和落库那份不一样"——刚流完上一章时它也成立，于是跟到
第二章就停了；要用"人真敲过字"。

### 编辑器第二次定形：照代码编辑器排

用户 2026-09-11 晚：「重新理解故事页面，重点是写作窗口，其他都是辅助功能」。

上一节那版在 1440×900 下量出来两件事：一章 343 字的 textarea 被算成
8803px 高（fit() 在版面还没排好、宽度很窄时量了一次，之后不再重算），
稿纸拉到 8 屏，右下角那排按钮在第一屏往下 8000px；对话面板 320px 从右下角
弹出，正好压住正文列的右半。根子不是样式：页面在滚、稿纸在滚、textarea
又靠 JS 撑高，**三层在抢同一个高度**，任何一层量错整页就垮。而对话要装
引用、来回、撤销、输入框，本来就是侧栏的体量，塞进弹窗只能盖字。

```
┌ 顶栏 ───────────────────────────────────────────────────────┐
│ 章节 220 │ 正文：独占滚动，铺到边，16px          │ 对话 340   │
│ 1 ✓ 343  │ 第 3 章 · 雨中告别               […] │ 默认收起   │
│ 2 ✓ 1120 │ 大纲那一句（可折）                    │ 引用       │
│▸3 ● 1431 │ 正文……                               │ 来回       │
│ 4 ⟳ 写着 │            ┌──────────────┐          │ 已落进 ✓ ↶ │
│ 5 —      │            │ ✨改 12 字  朗读 │ ←选中才出现 │ 输入框     │
│ ✨展开 13 │            └──────────────┘          │            │
├──────────┴──────────────────────────────────────┴────────────┤
│ 1431 字 · 已存       AI 展开中 3/16 [停] 跟着翻 ✓   对话  专注 │
└─────────────────────────────────────────────────────────────┘
```

- **正文格是唯一的滚动容器。** 路由上标 `wide`，外壳关掉页面滚动、不加
  最大宽度和内边距，页面自己排三栏。textarea 仍跟内容长，但只在这一格里
  长；宽度一变就重量（ResizeObserver），没排出来（clientWidth 为 0）不量。
- **正文铺到边，不卡行宽。** 第一版卡在一行 38 个字居中，两边各空出三分
  之一的屏幕，用户看了一句「左右两边是摆设？」「不能到边显示吗」。一行长了
  读起来要多扫一段，但那是读的事；写的人要的是眼前这块地全是自己的稿子。
  四边只剩 12px（「要留白干什么玩意」），第一个字不压在边线上就行。
- **整块都是纸。** 「点故事页面的下面光标为什么消失了」——短章的输入框
  只有半屏高，往下是滚动容器的留白，点上去就失焦。现在输入框 flex 撑到底，
  40vh 的滚动余量放进输入框自己的内边距，点在章头空当、边角上，mousedown
  拦住不失焦、光标落到末尾。
- **章节列表在左，替代下拉框。** 书的形状要一直看得见，尤其批量跑一个多
  小时的时候——这一栏同时就是进度条（写着…／砸了／●改了／字数／—）。收起
  后退化成章头上的下拉框，窄于 1100 自动如此。
- **对话停靠右栏，默认收起。** Ctrl+K 打开。没选中就改整章，选中了只改
  那一段。选中两字以上，正文格**底边中间**浮出「改 / 朗读」两个按钮，
  mousedown 拦掉不让输入框失焦。窄屏时右栏变成盖上来的抽屉。
- **存自动化。** 停笔 1.5 秒、换章、失焦、离开都存，状态栏写「存着…／
  已存」。五个存的入口全删，Ctrl+S 无声保留。**存稿走独立的一条
  useAction**：那个 composable 一次只跑一件事，而改一段要跑一分钟。存的
  那一会儿又敲了字，那一章仍算脏、再排一次；setStory 只摘掉手里和服务端
  一致的章，不整个清空——不然下一次刷新会拿旧的盖掉刚敲的。
- **AI 写字时锁章。** textarea 只读，章头「AI 正在写 [停]」，正在长的那
  一头一直留在视野里。之前人还能打字，下一个 token 一到 buf 就被覆盖。
  「跟着翻」是显式开关，点了别的章就关；五秒内敲过字不翻。
- **章头在正文里。** 第几章、大纲那一句（可折）、空章的「照大纲写这一章」；
  重写整章、从光标处朗读收进「…」——破坏性又少用的事不配常驻按钮。
- **空状态、草稿、「这本书」都在正文位置，同一框架。** 有了故事以后梗概、
  体量、重出大纲在左栏顶上那块「这本书」里，之前它们有了故事就消失了。
- **项目库在故事页默认收起**，和别处各记各的。

**第二步（还没做）**：textarea 底下垫一层同字体同宽的镜像算选区坐标。
有了它工具条才能贴着选区、AI 刚写那段才能加底色、正在流的位置才能画光标。

### 所有页面照故事页的样子

用户 2026-09-11：「重构所有页面的 UI，参考故事页面，突出重点，废话不要多，
UI 尽可能的简洁。」从故事页抽出来的规矩，套到其余每一页：

- **没有页头。** 顶栏已经说了在哪一页，StepHeader（编号徽标、大标题、
  一句 tagline）整个删掉。页头里的按钮挪到这一页顶上一条 `.toolbar`：
  左边是范围、筛选、读数，右边是动作。
- **没有解释性的段落。** card__sub、field__hint、notice、「为什么」那些句子
  全删。留下的只有三种：读数（压成一行）、报坏了的状态（一句话加修的
  按钮）、体检里的 fix。操作一个控件真需要的提示放进 `title` 或
  placeholder。
- **没有卡片。** 页面里的一节是一条细线加一个小标题（`.sec` / `.sec__t`），
  内容直接跟着。只有真正浮着的东西还带框：抽屉、弹窗、下载进度。
- **一个视图一个实心按钮。** 其余全是 ghost、small。
- **空状态一行字**：缺什么、去哪儿，不再是虚线框加大图标。
- 12px 的边距，和故事页一样；tab 是一行字带下划线。

一个坑：**子组件根元素的类名不能和 App.vue 里的 scoped 类同名。** 子组件的
根会带上父组件的 scoped 属性，项目页根元素叫 `.proj` 时，顶栏项目按钮的
`.proj { max-width: 11rem }` 套上来，整页被压成 176px 宽。`.ep` 同理。

### 朗读：引擎里新开的一个口子

`POST /api/tts/say`。在这之前 `llama_tts` 只在出片的配音那一步用，没有
"把这段字念出来"的接口。

- **念的是选中的那一段**，没选就从光标往下念。整章念完要好几分钟，而人在
  编辑器里想听的通常是刚改过的那几句顺不顺口。
- **一次最多 200 字**。Qwen3-TTS 一次合成上限 512 帧 / 12.5 Hz ≈ 41 秒，
  中文每秒五个字就是两百字出头；取 200 是落在上限里面一点——顶到上限时
  模型会把最后一句掐掉，掐掉那半句听起来像"念错了"。超了**不静默截断**。
- 退回估算后端时出来的是**等长静音**（那是配音阶段刻意的设计，在这儿没
  意义），所以响应里回后端名字，界面照实说——不然用户会对着一段没声音的
  音频以为是自己音箱坏了。

实测：27 字念出 7.36 秒；整章那次念前 200 字、37 秒。

## 六、迁移

- `story.json` 不存在时一切照旧走老路径，老项目打得开也跑得动。
- 「从已有剧集反推大纲」**还没做**：老项目现在能打开、能跑老路径，
  但接不到新流程上。要接的话得有这个动作。
- `Episode` 加 `chapter_refs` 指回来源章节；为空表示这一集不是从故事切出来的。
