# 故事优先重构方案

2026-09-11 定。分两块：**故事层**（引擎，本文第一到三节）和
**页面收成两页**（界面，第四节）。两块可以分别上，互不阻塞。

## 一、为什么改

原来写整季是这样的（`http/batch.cpp` 的 `post_script_series`）：

```
for i in 1..N:
    prompt = 一句梗概 + 最近三集剧本原文 + 已有角色名
    draft  = LLM(prompt)
    新建一集，存进去
```

`previous_context()` 只取最近三集，还按 4000 字符截断；集数 `episodes`
是个 1..20 的入参；角色库由 `post_bible` 从**第一集有内容的剧本**提。

四个后果，每条都直接来自上面三行：

| 现象 | 原因 |
|---|---|
| 没人规定第 N 集该发生什么 | 循环里除了梗概没有全局结构 |
| 写到第五集开始失忆，伏笔接不上 | 只带前三集、4000 字符 |
| 故事没有终点，写满 N 集就停 | 集数是人拍脑袋填的 |
| 角色和场景是增量拼的 | bible 从单集剧本提 |

最后一条最要紧：README 里「角色一致性做成结构约束」这条设计，**在集内成立，
跨集是漏的**——那个「全剧共用的资产库」其实是从第一集推出来的。

改成：**先有完整故事，从故事提人物关系和场景，再按每集时长把故事切成集。**

## 二、故事分三层，不是一次生成

一个二十集的故事十几万字，大模型一次吐不出来，也塞不回上下文。所以：

```
梗概（一两句）
  ↓
故事大纲（分章，每章三五句 + 人物关系 + 场景表）   ← 短，一次生成得完
  ↓
章节正文（逐章展开，每次带「全局大纲 + 人物表 + 上一章结尾」）
```

**中间那层是压缩的全局记忆。** 今天的失忆不是因为「逐集写」，是因为没有一份
压缩的全局状态可以每次都带上——只能带前三集原文，带不下就截断。有了大纲，
写第二十章时第二章埋的伏笔照样在上下文里。

### 用户给什么

**故事体量 + 每集时长**，不给集数。集数是算出来的。

什么约束都不给，模型写出来的故事长度是随机的：同一句梗概可能给一个三章就完的
段子，也可能铺开二十章。所以体量这个决定躲不掉，只是不该用「我要写 N 集」
来表达。

### 故事从哪来

三个入口，产物都是同一个 `Story`：

- **AI 写**：梗概 → 大纲 → 正文
- **粘贴**：已有的小说/剧本文本，切成章节
- **关键词**：给方向，走 AI 那条

联网搜热点**不做**：这是本地单二进制、进程内跑的程序，没有检索的路子，加进来
是新增依赖加合规问题。粘贴入口已经覆盖「我自己找到的素材」这个需求。粘别人的
作品是用户自己的事，界面上提一句版权自负，不内置抓取。

## 三、分集怎么算

见 `stages/story_plan.hpp`。要点：

1. **每集容量**按原文字数估：`prose_budget_chars(时长)`。
2. **切点只能落在钩子上**。短剧每集结尾必须是悬念、反转或情绪落点，这是完播率
   的要求，不能按字数硬切。章节里的候选钩子由大纲阶段标出来（`Chapter.hooks`），
   **章界永远是一个候选**。
3. 贪心：从当前位置往前一个容量，取离理想位置最近的那个候选。
4. **尾巴不单切**：剩下的不到 1.3 个容量就并成一集，宁可一集长些，也不留一个
   十几秒的尾巴。
5. **没有正文的章节按「一章一集」**。大纲阶段章节本来就是按情节单元分的，
   一章一集是合理的初始猜测；正文展开之后重算会更准。

字数换算那个系数（`kProseCharsPerSecond`）是**估的**。真实时长以配音为准——
这是 README 里「配音先行」那条规矩，分集表只是建议，人可以调，成片之后某集
明显超或欠，界面上提示重算。

## 四、页面收成两页

八步其实只有两种作业：**写整部剧** 和 **修这一集**。路由里的 `PHASES`
（series / episode）早就把这条界画对了，只是画完之后又铺成了八页。

```
顶栏：  场记 · 项目名 ▾ │  故事    ep02 五年前那把伞 ▾ │  ●引擎  ⚙
```

### 故事页

这部剧的全貌：讲什么、分几集、每集覆盖哪几章、每集拍到哪了。

- **分集就是章节之间那条线**，不是另一张表。每集的进度长在线上。
- 右栏是**索引不是画廊**：名字、缩略图、一个缺参考图的警示点。点名字开抽屉定妆。
  人物和场景本来就是从故事里提的，摆在故事旁边才看得出这层关系。
- 一个主动作：写故事 → 有分集后变「全部出片」。

没有：集数输入框、设定页、分集页、选题卡、草稿卡、整季进度卡、剧本正文，
以及右栏里任何可编辑的东西。

### 这一集页

`剧本 │ 镜头 │ 成片` 三个视图对着同一集，**成片视图底下直接是发布表单**——
看完这一集就发出去是一个连贯动作，不值得单开一页。

没有：发布页、成片页、场景页、步骤抬头、跨页 EmptyState、常驻体检卡
（只在真拦住时作为出片按钮下面一行红字）、一排六个批量小按钮
（收成「已选 N 镜 ▾」）。

### 继承关系

**主干只能有一个**，选「最难重写的那个」；其余都是搬过去的器官。

| 新页 | 主干 | 搬进来的 | 丢掉 |
|---|---|---|---|
| 启动器 | ProjectView | | 画面卡、画风卡（→设置）、StepHeader、stepbar |
| 故事 | ScriptView | | 集数下拉、整季进度卡、单集编辑器（→这一集） |
| 这一集 | ShotsView | ScriptView 的单集编辑器、FilmView 整页、PublishView 的表单 | 常驻 blocked 卡、六个批量按钮 |
| 设置 | SettingsView | ProjectView 两张卡、PublishView 的账号 | |
| 抽屉 | ShotsView 的 drawer 壳 | Characters/ScenesView 的展开体 | 那两页的整页外框 |
| 外壳 | App.vue | | StepRail、ContextBar、stepbar |

**别让一个新页有两个主干。** 「这一集」若既继承 ShotsView 的骨架又继承
ScriptView 的页面骨架，结果是两套状态机并存——那正是今天 ScriptView 自己的病：
它同时是全剧编辑器和单集编辑器，所以谁也做不好。搬进去的是**编辑器**，不是那一页。

**页面数是给用户的，文件数是给代码的，不用对齐**：

```
StoryView.vue      故事页（壳 + 分集切线）
  StoryChapters.vue
  StoryIndex.vue
EpisodeView.vue    这一集页（壳 + 三视图切换 + 出片）
  EpScript.vue
  EpShots.vue      ← ShotsView 主体原样搬进来，不改内部逻辑
  EpFilm.vue       ← FilmView + 发布表单
```

消失的文件：CharactersView、ScenesView、FilmView、PublishView。内容都有去处，
不是删功能。

## 五、分期

| 期 | 做什么 | 依赖 |
|---|---|---|
| 1 | `models/story` 数据层 + `stages/story_plan` 分集算法 + 单测 | 无 |
| 2 | 大纲生成 stage（提示词 + schema + 解析）、`/api/story` | 1 |
| 3 | bible 输入源从单集剧本换成故事大纲 | 2 |
| 4 | 写集改成「展开指定章节段落」：前情从「前三集原文」换成「全局大纲 + 本集章节正文 + 上一集结尾」 | 2 |
| 5 | 外壳收成一条 + 这一集页合并 | 无（纯前端，可与 1–4 并行） |
| 6 | 故事页落地 | 2、5 |
| 7 | 逐章正文生成（长故事）、分集表拖拽调整 | 6 |

## 六、迁移

- `story.json` 不存在时一切照旧走老路径，老项目打得开也跑得动。
- 另给一个「从已有剧集反推大纲」的动作，把老项目接上新流程。
- `Episode` 加 `chapter_refs` 指回来源章节；为空表示这一集不是从故事切出来的。
