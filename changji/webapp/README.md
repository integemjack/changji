# 场记 Web 平台

Node + Vue 3 重写的界面层。把整条生产线做成八步引导，分两段：

```
全剧（做一次）    项目 → 剧本大纲 → 角色
分集（每集重复）  场景 → 分镜 → 制作 → 成片 → 上传至平台
```

前三步的产物整部剧共用：剧本大纲是全剧讲什么、分几集，角色是全剧同一批人。
后五步对着某一集干活，顶栏的集号决定在哪一集上操作。段界画在侧边导航上，
免得用户以为角色也要每集重出一遍。

每一步都能让大模型代劳，每一步的结果都看得见——不是一堆 JSON，是
项目卡片、剧本对白视图、角色三视图、场景空景图、分镜时间轴、镜头缩略图墙、
带分镜跳转条的播放器。

## 角色和场景为什么都是全剧一份

分镜表里只存 `char_id` 和 `location_id`，外观和空间的描述由程序从资产库
拼接，逐字节相同——这是跨镜头一致的唯一手段。每集各存一份拷贝的话，
同一个安保室在第一集和第五集会长得不一样，而这正是这套系统要防的事。

所以库是全剧的，场景这一步只是把镜头对准「这一集用到的那几个」：出分镜
之前按这一集的剧本补新场景，出了分镜之后按镜头实际引用的 id 分成
「本集用到」和「其他集的」两组。AI 补设定默认只加新的，不动老的——
第五集冒出一个新角色时，不该把前四集主角的脸重新想一遍。

## 为什么是两层

真正的流水线在引擎那边（`../cpp`）。Node 这层只做三件事：

- 把打包好的前端发出去
- 把 `/api/*` 原样转给引擎
- 管两件引擎管不了的事：引擎地址本身，和上传平台的投递配置

中间加这一层的理由很实际：引擎地址填错的时候，用户仍然需要一个能打开的
界面去改它。前端直连引擎的话，填错地址就等于把自己锁在门外。

流水线逻辑不在 Node 里重写。两套实现迟早会漂。

## 跑起来

先起引擎：

```bash
changji --port 8080
```

**只是想用界面的话不需要这一层。** 打包好的前端嵌在引擎二进制里，
起了服务打开 http://127.0.0.1:8080 就是同一套。这一层是给
"引擎在别的机器上"和"改前端"两种情况用的。

再起这一层：

```bash
cd webapp
npm install
npm run dev          # 前端 5173，Node 5174，改代码热更新
```

浏览器打开 http://127.0.0.1:5173

部署时先打包再只跑 Node：

```bash
npm run build
npm start            # 默认 5174，前后端同一个端口
```

或者用 compose 一条命令拉起全套（Web 平台 + 引擎 + ollama）：

```bash
docker compose -f ../docker-compose.yml up -d
```

然后打开 http://localhost:5174 。镜像分两段构建，vite 和它那一堆
devDependencies 留在构建段，运行段只有 express 和打包好的静态文件。

## 和引擎自带的那个界面是什么关系

**是同一套。** 引擎把这里 `npm run build` 出来的 dist 嵌进了二进制
（`cpp/tools/gen_webapp.py` 生成 `bundled_webapp.inc.hpp`），
起了服务打开 8080 根路径就是它。

早先 8080 上挂的是另一个手写的单页 HTML，两套功能重叠。那一份随
Python 引擎一起删了，现在只有一套界面、两个入口：

| 入口 | 什么时候用 |
|---|---|
| 引擎的 8080 | 平时。不用装 Node，前端在二进制里 |
| 这一层的 5174 | 引擎在别的机器上（地址填错了还能打开界面改回来），或者在改前端 |

**改了前端要重新嵌一次**，不然二进制里还是旧的：

```bash
npm run build && python cpp/tools/gen_webapp.py
```

## 配置

| 项 | 在哪儿改 | 存在哪儿 |
|---|---|---|
| 引擎地址、请求超时 | 设置页「引擎」 | `%APPDATA%/changji/webapp.json` |
| 大模型 API 地址、模型、密钥 | 设置页「大模型」 | 引擎的 `config.toml` |
| ComfyUI API 地址、超时、重试 | 设置页「ComfyUI」 | 引擎的 `config.toml` |
| 配音后端与引擎 | 设置页「配音」 | 引擎的 `config.toml` |
| 画质档位、装配规格、质量闸门 | 设置页对应小节 | 引擎的 `config.toml` |
| 投递目标（平台、目录、webhook） | 上传页 | `%APPDATA%/changji/webapp.json` |

环境变量优先级最高，被顶住的字段界面上会标出来——不标的话用户会以为
没保存上，重启回来发现又变回去了。

Node 这层认两个环境变量：

- `CHANGJI_ENGINE_URL` 引擎地址
- `CHANGJI_ENGINE_TIMEOUT_MS` 单次请求超时
- `PORT` / `HOST` 监听端口

## 上传至平台是怎么回事

各家平台的开放接口都要资质和密钥，这里不假装能替用户登录。投递做的是：
把成片和一份填好的元数据（标题、简介、话题）复制到目标目录，或者 POST 给
用户自己配的 webhook，由那边的脚本或第三方工具接手上传。

好处是在没有任何平台密钥的机器上也能把全流程跑通，而且投递前会拿平台的
画幅和时长上限做一次自检——这两项是最常被退回来的，投出去之前就能算出来。

## 手机

同一套代码，860px 以下换布局：侧边八步收成抽屉，分镜编辑器由两栏折成一栏，
成片页播放器和片单上下排。开发时 Vite 监听 `0.0.0.0`，手机连同一个局域网
直接打开电脑的 IP 就能看。

## 目录

```
webapp/
├── server/src/
│   ├── index.js          Express 入口，静态资源 + 转发
│   ├── config.js         Node 侧配置（引擎地址、投递目标）
│   ├── engine.js         引擎客户端与流式转发
│   └── routes/
│       ├── settings.js   设置页的聚合接口
│       ├── publish.js    投递目标与投递记录
│       └── flow.js       八步进度判定（只写在这一处）
└── client/src/
    ├── api/              接口封装与枚举中文映射
    ├── stores/           会话（当前项目与集）、运行状态、界面杂事
    ├── components/       壳、步骤导航、状态灯、空状态、进度条
    └── views/            八步各一页，外加设置页
```
