# 场记 Web 界面

Vue 3 写的界面层，**打包之后嵌进引擎二进制**。把整条生产线做成八步引导，
分两段：

```
全剧（做一次）    项目 → 剧本大纲 → 角色
分集（每集重复）  场景 → 分镜 → 制作 → 成片 → 上传至平台
```

前三步的产物整部剧共用：剧本大纲是全剧讲什么、分几集，角色是全剧同一批人。
后五步对着某一集干活，顶栏的集号决定在哪一集上操作。段界画在侧边导航上，
免得用户以为角色也要每集重出一遍。

每一步都能让大模型代劳，每一步的结果都看得见——不是一堆 JSON，是
项目卡片、剧本对白视图、角色三视图、场景空景图、分镜时间轴、镜头缩略图墙、
带分镜跳转条的播放器。

## 角色和场景为什么都是全剧一份

分镜表里只存 `char_id` 和 `location_id`，外观和空间的描述由程序从资产库
拼接，逐字节相同——这是跨镜头一致的唯一手段。每集各存一份拷贝的话，
同一个安保室在第一集和第五集会长得不一样，而这正是这套系统要防的事。

所以库是全剧的，场景这一步只是把镜头对准「这一集用到的那几个」：出分镜
之前按这一集的剧本补新场景，出了分镜之后按镜头实际引用的 id 分成
「本集用到」和「其他集的」两组。AI 补设定默认只加新的，不动老的——
第五集冒出一个新角色时，不该把前四集主角的脸重新想一遍。

## Node 那一层去哪了

**2026-09-12 整个删掉了。**

原来这儿还有个 `server/`（Express），干三件事：发前端、把 `/api/*` 转给
引擎、管引擎地址和投递配置。留着它的理由当时写的是"引擎地址填错的时候
还得有个能打开的界面去改回来"。

它现在一件都不干了：

- **发前端** —— 打包好的 dist 已经嵌进引擎二进制（`cpp/tools/gen_webapp.py`
  生成 `bundled_webapp.inc.hpp`），8080 根路径就是它。
- **转发 `/api/*`** —— 前端和引擎已经在同一个端口上，没有跨源可转。
- **`/bff/*`** —— 由引擎自己答（见 `cpp/src/http/bff_routes.hpp`）。

于是那一层剩下的只有"把请求从一个进程转给另一个进程"，而两头是同一个
进程。留着它的代价是实打实的：它那份八步判定（`routes/flow.js`）和引擎里
`http/flow.cpp` 是**同一套规则的两份实现**，早就漂了——CI 上那条
"步骤表和判定的键要对得上"从 2026-09-11 起一直红着，把整条发布流水线
卡在第一格，而红的是一份谁也没在跑的代码。

投递（上传至平台）那一套也在那一层里，跟着一起没了。引擎这边
`/bff/publish/*` 返回的是空形状加一句说明，不是 404——前端 `Promise.all`
挂一个整页就是红框，用户分不清"没做"和"坏了"。

## 跑起来

平时用界面**不用装 Node**：起引擎，打开 8080 就是。

```bash
changji --port 8080
```

改前端的时候才要这一套：

```bash
cd webapp
npm install
npm run dev          # Vite 开发服务器，改代码热更新
```

Vite 的开发服务器把 `/api` 和 `/bff` 代理到 8080 的引擎上（见
`client/vite.config.js`），所以开发时引擎照样要起着。

**改完要重新嵌一次**，不然二进制里还是旧的：

```bash
npm run build && python3 ../cpp/tools/gen_webapp.py
```

CI 里这两步在「前端（打包 + 嵌进头文件）」那一格，产物当构建缓存传给
六个平台的构建格子——所以**提交时 `bundled_webapp.inc.hpp` 也要一起提**，
本地编出来的二进制才和发布的是同一套界面。

## 配置

界面上改的**全都落在引擎的 `config.toml` 里**（Node 那层没了，也就没有
第二个配置文件了）：

| 项 | 在哪儿改 |
|---|---|
| 大模型 API 地址、模型、密钥 | 设置页「大模型」 |
| 配音后端与地址 | 设置页「配音」 |
| 模型目录、模型选型 | 初始化页 |
| 画质档位、装配规格、质量闸门 | 设置页对应小节 |

环境变量优先级最高，被顶住的字段界面上会标出来——不标的话用户会以为
没保存上，重启回来发现又变回去了。

## 上传至平台

**这一套随 Node 那层一起删了**（2026-09-12），引擎这边没有接。

它原来做的是：把成片和一份填好的元数据复制到目标目录，或者 POST 给用户
自己配的 webhook，由那边的脚本接手上传——各家平台的开放接口都要资质和
密钥，那一层从不假装能替用户登录。真要这个功能的话，是在引擎里重做一遍，
而不是把 Node 那层捡回来。

## 手机

同一套代码，860px 以下换布局：侧边八步收成抽屉，分镜编辑器由两栏折成一栏，
成片页播放器和片单上下排。开发时 Vite 监听 `0.0.0.0`，手机连同一个局域网
直接打开电脑的 IP 就能看。

## 目录

```
webapp/
└── client/src/
    ├── api/              接口封装与枚举中文映射
    ├── stores/           会话（当前项目与集）、运行状态、界面杂事
    ├── components/       壳、步骤导航、状态灯、空状态、进度条
    └── views/            八步各一页，外加设置页
```
